# Halv app translation guide

## Runtime model

The app uses English source strings as catalog keys. The runtime reads files from `src/i18n/catalogs/`.

The extractor generates `src/i18n/sources.json`. This file is the source of truth for catalog keys.

A catalog can omit a source key during an active translation round. The runtime returns the English source for that key.

A missing translation is legitimate. The missing translation does not block other translation work.

## Workflow for the next translation round

1. The developer routes more components through `useT()`.
2. The developer runs `node scripts/i18n-extract.mjs`.
3. The translator fills the new keys included in the translation round.
4. The translator runs `node scripts/i18n-audit.mjs`.
5. The developer resolves each failure and reviews each warning.
6. The developer runs `pnpm test:unit`.
7. The developer runs `node scripts/i18n-extract.mjs --check`.

The audit checks all ten locales when the command has no locale argument.

The reviewer can audit selected locales. For example, run `node scripts/i18n-audit.mjs fr ja`.

The audit prints one coverage line for each locale. The line shows translated keys, total source keys, and the percentage.

The release gate can require complete catalogs. Run `node scripts/i18n-audit.mjs --require-complete`.

The reviewer can combine the flag with locale arguments in any order. For example, run `node scripts/i18n-audit.mjs fr --require-complete ja`.

## Translation rules

### 1. Keep exact keys

The translator copies each key from `src/i18n/sources.json`. The translator does not retype keys.

Each key must match every byte. Some keys contain the middle dot and typographic punctuation.

### 2. Handle missing translations

The catalog can omit a source key. The runtime uses the English source until the translator adds the key.

The release gate uses `--require-complete` when each catalog must contain every source key.

### 3. Preserve placeholders

Each translation must contain the same placeholder names as its source. The translator can change their order.

The translator must not translate, rename, add, or remove a placeholder.

Current placeholders include these names:

- `{name}`, `{error}`, `{count}`, `{saved}`, `{cap}`, and `{date}`
- `{plan}`, `{port}`, `{version}`, `{percent}`, `{project}`, and `{provider}`
- `{kind}`, `{personality}`, `{status}`, `{conversations}`, and `{messages}`
- `{projects}`, `{workspaces}`, and `{memories}`
- `{amount}`, `{tokens}`, and `{source}` (dollars saved, ADR 0015)
- `{low}` and `{high}` (the ends of a routing estimate range, ADR 0016), and `{model}`
- `{memory}` and `{terminals}` (the resource chip in the status bar)

`{amount}` holds a formatted dollar amount, for example `$0.42`. The app formats it in the locale, so the translation keeps the placeholder as one unit.

### 4. Preserve invariant terms

The translator must keep these terms unchanged and in Latin script:

- `Halv`, `Pro`, `Claude`, `Codex`, `ChatGPT`, `OpenAI`, and `Anthropic`
- `Kimi`, `Grok`, `Ghostty`, `macOS`, `Windows`, and `Linux`
- `MCP`, `CLI`, `API`, `JSON`, `URL`, `Git`, and `GitHub`

This rule applies to every locale. It also applies to Japanese, Korean, and Chinese catalogs.

`Halv Engine` follows the product glossary instead of this invariant term rule.

### 5. Use non-empty values

Every catalog value must be a string. Every value must contain text after trimming.

### 6. Remove stale keys

Every catalog key must exist in `src/i18n/sources.json`. The translator must not add another key.

### 7. Preserve shell text

The source `Fallback without pipx:` names a command. The translator must keep `pipx` unchanged.

### 8. Prevent control collisions

One control can show several options together. Each option in these groups needs a distinct translation:

- `active`, `disabled`, and `invalid`
- `never`, `background`, and `always`
- `system`, `light`, and `dark`
- `Healthy`, `Needs attention`, and `Unavailable`
- `Settings` and `Preferences`

The translator uses the meaning "turned off" for `disabled`. The translator uses "rejected" or "not valid" for `invalid`.

`Settings` is the panel title. `Preferences` is a category in that panel.

The translator uses the target operating system term for the `Preferences` category.

### 9. Distinguish the Unlimited plan from quantities

`Upgrade to Unlimited` names the paid plan. Its translation must keep `Unlimited` unchanged and in Latin script.

The checkout uses the plan identifier `unlimited`. The plan name works like `Basic` in other plan text.

The bare source `Unlimited` means that a number input has no limit. The translator must translate this quantity.

The translator must also translate `Unlimited` in these sources:

- `Saved. Concurrent child agents are Unlimited.`
- `Enter a positive whole number, or leave it empty for Unlimited.`
- `Optionally cap how many child agents can run at once to help control usage. Leave this empty for Unlimited.`

### 10. Limit translation length

Short labels use fixed button space. A source under 25 characters needs a translation under 1.6 times its length.

The translator chooses the shortest natural term. The audit warns when any translation exceeds 1.8 times its source length.

For `Retry automatic setup`, use the target equivalent of "Try again".

## UI style

The translator uses short, natural text. The translator does not add unnecessary words.

Buttons and menus use the standard UI imperative for the locale.

Progress text that ends in `...` keeps `...` or uses `…`. The translation keeps the same shape.

A sentence that ends with punctuation keeps terminal punctuation.

The translator follows source capitalization when the target orthography permits it.

These enum labels stay lowercase unless the target orthography requires capitals:

- `active`, `always`, `background`, `dark`, `disabled`, and `friendly`
- `invalid`, `light`, `never`, `pragmatic`, `system`, and `unknown`

The translator uses the formal or neutral register of the target operating system.

German and Dutch text addresses the user as macOS does.

The translator uses one term for each concept throughout one catalog.

## Product glossary

The translations of the Halv website (halv.ai) are the terminology glossary for product vocabulary.

The translator reuses terms for `Halv Engine`, language, closing, savings, tokens, terminals, and agents.

The translator also checks the glossary meaning for `Unlimited` before choosing a translation.

## Catalog format

The translator writes UTF-8 without a byte order mark. The catalog ends with one newline.

The translator writes one flat JSON object. The translator uses two spaces and adds no comments.

The translator keeps keys in the same order as `src/i18n/sources.json`.

## Audit results

Failures include stale keys, invalid values, placeholder changes, and lost invariant terms.

Failures also include a missing final newline or a byte order mark. Any failure makes the audit exit nonzero.

Warnings include missing keys and possible translation or layout defects. Warnings do not change the audit exit code.

The `--require-complete` flag changes missing keys from warnings to failures.
